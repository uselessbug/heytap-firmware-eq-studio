# Enco X4 固件结构与 EQ 映射

本记录来自用户提供的 Enco X4 112 / 116 固件和 APK 静态分析。它描述已验证的样本，不保证后续版本或其他机型保持相同布局。

## OPKG 容器

已验证样本为单段 OPKG v1。

| 项目 | 已确认的结构 |
| --- | --- |
| 整包 SHA-256 | 字节 10..41，覆盖字节 42 至文件末尾 |
| 散列类型 | hashId = 3 |
| 数据块头 | 32 字节，8 个小端 uint32，magic = 0x55AA66BB |
| 原始分块大小 | 256 KiB |
| 压缩 | LZMA-alone，属性头 5d00000004，64 MiB 字典 |
| 校验 | 压缩块 / 原始块 CRC 和整包 SHA-256 |
| 保留规则 | 未修改块使用原始压缩字节，未知扩展字段保留 |

重新封包必须先验证输入，保持原始数据长度，验证导出后的全部 CRC / SHA，并确认声明范围之外的原始字节未变化。

## EQ 记录

每条记录 300 字节：

- 两个 float32 增益；
- 一个 uint32 滤波器数量；
- 最多 18 个滤波器槽位，每槽按顺序为 uint32 类型、float32 增益 dB、float32 频率 Hz、float32 Q。

记录可表示为小端 `<ffI` 加 18 个 `<Ifff`。参数区共有 184 条记录，四组表各含 46 个指针，表后有空指针。应通过指针读取记录，不能只假设固定序号对应固定地址。

| 样本 | 原始数据长度 | EQ 区间，末地址不含 | 四组指针表起始地址 |
| --- | ---: | --- | --- |
| 112 | 8,717,764 | 0x735758..0x742EF8 | 0x84AE58、0x84AF14、0x84AFD0、0x84B08C |
| 116 | 8,650,680 | 0x724F04..0x7326A4 | 0x83A840、0x83A8FC、0x83A9B8、0x83AA74 |

四组名称按表顺序为 `other_output2`、`india_output2`、`other_output1`、`india_output1`。目前没有证据将它们直接命名为左耳 / 右耳。

| 固件类型值 | 含义 |
| ---: | --- |
| 0 | Low shelf |
| 1 | Peak |
| 2 | High shelf |
| 3 | Low pass |
| 4 | High pass |
| 5 | All pass |

类型 5 不能解释为 Notch。固件槽位上限 18 和运行时其他代码中的 40 槽容量属于不同结构。

以下组合适用于已检查的选择函数和当前命名信息。

| 1 | 0 |
| 2 | 1 |
| 3、4 | 2 |
| 5 | 3 |
| 6 | 4 |
| 7 | 5 |
| 9 | 6 |
| 8 | 7 |

已观察到的未识别状态走索引 8 的独立回退路径。特殊标志使用索引 45，该记录保留。其具体声学用途和用户界面名称尚不应推断。

每个普通预设对应四组路径 × 九个状态，即 36 条记录。替换两个预设应更新 72 条对应记录，并检查每条记录所属的表和状态。

## 版本及其他元数据

当前桌面 `metadata.py` 已重新从真实 112/116 读取并核对 getter，独立实现等宽字段编辑和 12 字节补丁。当前 Actions 在 Linux/Windows 均通过 2,000 次独立指令执行检查；不是沿用丢失源码阶段的报告。旧 CLI 仍不修改版本。真实输入的重新封包/重开识别见 [元数据验证](metadata-real-validation.json)。

已确认的容器头字段包括 package type、product ID、manufacturer、硬件版本、section ID、section 名称、软件版本和构建时间。已识别的原始数据文本字段包括 `SW_VER`、`BUILD_DATE`、`REV_INFO`。

- 等宽 ASCII 文本可在明确边界内修改。
- 软件版本涉及容器字段、嵌入文本及运行时返回值，需同步处理。
- 已验证的运行时 getter 可替换为 12 字节 Thumb 指令，在 r0 指向位置写入三个版本字节。
- 地址、长度、分区布局和自动校验字段不属于自由文本编辑项。
- 未识别的版本 getter 保持只读。

运行时版本补丁已通过 ARM Unicorn 执行检查：000..999 共 1,000 个版本，每个在对齐和未对齐 SRAM 地址运行，总计 2,000 次；检查目标三个字节、相邻保护字节及 r1 / r4 保持。

## 新固件和新机型的适配

自动扫描可以发现符合参数约束的记录以及连续指针表，并展示候选地址、滤波器和增益。可靠写入还需要验证产品、选择逻辑、滤波器实现、表语义及版本 getter。

因此，新 ID 或索引变化可以被发现，但不能仅凭相似数据结构自动认定名称并允许写入。适配器应以结构验证和代码指纹共同决定写入能力；未知布局先提供只读检查。

本地已验证两个给定版本的修改与重新封包，尚未在耳机上刷写验证。
